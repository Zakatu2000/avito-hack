## Проблема и целевой результат

В репозитории команды нужно подготовить AI-часть прототипа AI-buddy «Первый PR». Целевой сквозной сценарий: стажёр не может открыть учебный репозиторий, агент проверяет доверенный контекст, объясняет причину, предлагает заявку, после подтверждения сервера показывает её статус, а после отдельного одобрения и фактической выдачи права сообщает следующий шаг.

Моя зона ответственности — только AI A1–A6: основание сценария, SDD, безопасное чтение контекста, оркестрация диалога, прямой OpenAI-совместимый API провайдера, демо-режим, evals, метрики и материалы для защиты. Сервер остаётся единственным владельцем прав, записи заявок и изменения состояния.

## Корректировка по фактической сборке команды (2026-11-10)

Источник: презентация сборки (`delivery/presentation.pdf`), командная серверная ветка. Ветка `AI` перебазирована поверх неё; фактические события сверены с кодом:

1. **Backend — Flask + PostgreSQL** (фактически), Go остаётся прод-ориентиром Авито. Интеграция AI — **in-process** вызов `Agent.respond(text, tools)` через фабрику `BUDDY_AGENT_FACTORY` и `AgentRunner` (тайм-аут 10 с, семафор 4, серверная валидация решения). HTTP-сервис `POST /internal/ai/respond` — опциональный адаптер, не основной путь.
2. **Контракт существует**: `contracts/agent.md` v1.0.0 + `contracts/openapi.yaml` v1.3.0 + 13 примеров (B1 выполнена). Временная фикстура A0 заменена зеркалом реального контракта (A0.1).
3. **Словари контракта**: `effectiveAccess ∈ {unknown, missing, granted}`; `requestStatus ∈ {pending, approved, rejected}`; `AgentDecision = {kind, text, sourceId, aiMode}` ровно с этими ключами, `kind ∈ {answer, clarify, propose_access, handoff}`; `sourceId ∈ {None, текущий разрешённый sourceId}`; `aiMode` обязан совпадать с серверным режимом (фабрика задана ⟺ live).
4. **Инструменты чтения** строит сервер: `current_task()`, `instruction()`, `effective_access()`, `current_request()`; без userId, скоуп — текущее назначение; скрытый объект читается как отсутствующий; ошибка чтения права = `unknown`, не «нет права».
5. **События** (A6 сверяется с ними): конверт `{eventId, name, occurredAt(UTC), assignmentId}`; имена `blocker_reported`, `request_created`, `access_granted`, `task_link_opened`. Отличие зафиксировано: `task_link_opened` - свидетельство начала работы; фактическое начало в пилоте требует отдельного наблюдения. 9 событий из плана сверены и закрыты в A6.
6. **Покрытие команды**: 88,48% (699/790 строк server/). AI считается отдельно по `ai/` (цель ≥90%), суммирование без двойного учёта — B6.
7. **Демоданные сборки**: `task-01` «Открыть README учебного репозитория», ресурс `repo-intro`, источник `demo-guide`, `prop-01`, `req-01`.
8. Синхронный интерфейс агента обоснован вызовом из `ThreadPoolExecutor`; HTTP-клиент провайдера — один на процесс, тайм-аут ниже бюджета AgentRunner.

### 4. A4 — прямой OpenAI-совместимый API провайдера и воспроизводимый режим

- Сделать адаптер провайдера через OpenAI-compatible HTTP API: `base_url`, имя модели, ключ из переменной окружения, тайм-аут, лимиты токенов, повтор только для безопасных запросов.
- Изолировать провайдер за интерфейсом вроде `LLMProvider.complete(...)`, чтобы реализация провайдера проходили одни и те же тесты.
- Разделить системную политику, проверенные факты и пользовательский вопрос; не передавать провайдеру внутренние роли и секреты.
- Использовать `response_format={"type":"json_object"}`, явно включать слово `json` и пример JSON в prompt; проверять `finish_reason=="stop"` и отклонять `length`, `content_filter`, `aborted`.
- Обрабатывать пустой `message.content` одним retry в пределах общего тайм-аута; после повторной ошибки возвращать `provider_unavailable`.
- Не использовать `json_schema`, если конкретный endpoint провайдера его не поддерживает; модель задавать только через env.
- Добавить явно включаемый `demo`/stub-режим без ключа для воспроизводимых тестов и защиты. В каждом результате возвращать `aiMode`.
- При ошибке/тайм-ауте провайдера возвращать понятное состояние `provider_unavailable`, без ложного успеха и скрытого переключения.
- Подготовить `.env.example`/README-инструкцию для Web 2 и пример полного обмена для Web 1. Реальный ключ не коммитить и не логировать.
- Основной runtime — OpenAI-совместимый провайдер; качество runtime-ответов измеряется только на нём.

## Критерии готовности моей части

- SDD и источники покрывают все состояния основного сценария и различают факты, демоданные и гипотезы.
- `Agent.respond` типизирован, валидирует вывод, не меняет права/заявки и не раскрывает закрытые сведения.
- Провайдер подключается через конфигурацию без секретов, а demo-режим воспроизводим и явно маркирован.
- Evals проверяют безопасность, отказоустойчивость, перефразирование и восстановление состояния.
- Метрики и события пригодны для пилота и защиты.
- Web 2 может подключить AI через контракт без ручных неявных соглашений; общий путь запускается из чистой копии.
