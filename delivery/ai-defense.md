# AI-defense: ответы для защиты (A6)

Владелец — AI. Опирается на `docs/sdd/agent.md`, `docs/sdd/cases.md`,
`docs/qa/agent.md`, `docs/events.md`, `docs/pilot.md`, контракт
`contracts/agent.md` v1.0.0 и код `ai/`.
Дополнено при интеграции (integration/final): событие `access_granted`,
тайм-ауты, повторная проверка контекста.

## Что делает LLM — и что делает сервер

- **LLM (live-режим, OpenAI-совместимый провайдер)** интерпретирует намерение
  сообщения из закрытого набора (`blocker_access`, `ask_next_step`,
  `ask_request_status`, `ask_mentor`, `off_topic`, `unclear`) и формулирует
  текст ответа. Намерение — только вход политики: `kind`, `sourceId` и
  идентификаторы всегда выбираются из фактов сервера; намерение может
  повлиять лишь на выбор clarify/propose, когда факты допускают заявку
  (право missing, заявки нет). Текст LLM проходит проверку на непротиворечие
  фактам (ID ⊆ факты, статусы/«право выдано» только при подтверждении) —
  нарушение → детерминированный текст (A3, `ai/agent/policy.py`).
- **Демо-режим** (основной для допуска и CI) работает без ключа и LLM:
  полностью детерминирован, воспроизводим, помечен `aiMode=demo`.
- **Сервер** владеет сессией, правами, заявками, транзакциями, событиями и
  идемпотентностью; сохраняет предложение до показа; перепроверяет
  полномочия при confirm; валидирует каждое решение агента
  (`AgentRunner`: точные ключи, `kind` из словаря, `aiMode` совпадает,
  `sourceId` — только разрешённый).

## Почему права не принадлежат AI

Агент получает только read-only инструменты, собранные сервером для текущей
сессии (без userId, скоуп — текущее назначение). У агента нет ни записи, ни
прямого доступа к БД, ни cookies. Решение `propose_access` — лишь данные;
заявку создаёт сервер после явного подтверждения стажёра, право выдаёт
отдельный шаг демооператора. Ответ модели не считается доказательством
действия (инвариант I-07).

## Какой контекст видит провайдер

Только вопрос стажёра и уже разрешённые факты текущего назначения: задача,
фрагмент разрешённой инструкции, признак доступа и статус заявки. Сессия,
ключи и номер заявки не входят в запрос модели. Пользовательский текст и
инструкция трактуются промптом как данные.

## Честные ограничения

- **Живой вызов провайдера в финальной сборке не проверен** (нет ключа в
  сессии сборки): механика покрыта моками (`httpx.MockTransport`) и
  live-моками намерений в evals; поведенческий live-eval — отдельный прогон
  `python -m evals.runner --live`.
- Исторические smoke-запросы GLM (10 ноября, 3 синтетические ситуации)
  выполнялись предыдущей сборкой классификатора — в этой версии кода не
  перепроверялись и точность не устанавливают.
- Учебный процесс заявки — синтетический (DEMO-03), не регламент Авито;
  замена адаптеров при внедрении — `docs/integration.md` (Web 2).
- Покрытие строк ≠ доля успешных eval-ответов; отчёты не смешиваются.
- Ориентиры 40–48/55–65 часов наставника — вся его работа, не обещанная
  экономия (см. `docs/pilot.md`).

## Сбои и режимы

Сбой провайдера → типизированное исключение → сервер отвечает 503
`unavailable`; ложного успеха и скрытой подмены demo↔live нет (сервер
отклоняет решение с чужим `aiMode`). Истёкшая сессия — 401 до вызова агента.
Пустой ответ модели (json-режим OpenAI-совместимого API заменяет не-JSON
пробелами) — один retry, затем `provider_unavailable`. После ожидания модели сервер повторно
проверяет сессию и контекст; при изменении — 409 без показа устаревшего
ответа. Бюджет раннера (`BUDDY_AGENT_TIMEOUT`) строго превышает тайм-аут
провайдера — иначе сервер не стартует.

## Эскалация к наставнику

Агент передаёт вопрос наставнику (`handoff`), когда: задача не назначена;
заявка отклонена и нужна причина; факты противоречивы после уточнения; запрос
вне разрешённых данных или полномочий; тема чувствительная (вне области
кейса). Агент называет, чего не хватает, и не выдумывает факты (CASE-03/11).

## Проверяется ли польза

В контролируемом пилоте сравниваются время до заявки (M1), время ожидания
права (M2, событие `access_granted`), обращения к наставнику (M3) и
наблюдаемый возврат к задаче (M4) — `docs/pilot.md`. Текущие метрики — план
испытания; экономия времени пока не измерена.

## Запуск (AI-зона)

```powershell
python -m venv .venv; .\.venv\Scripts\python -m pip install -e "ai[dev]"
cd ai
..\.venv\Scripts\python -m pytest --cov     # 92 теста, 100%
..\.venv\Scripts\python -m evals.runner     # 29/29 PASS (demo)
```

Подключение к серверу (B4): `pip install -e ai` +
`BUDDY_AGENT_FACTORY=agent.factory:create_agent` только вместе с
`AI_MODE=live` + `AI_*` (алиасы `DEEPSEEK_*`; иначе сервер корректно отклонит
решения по `aiMode`).
