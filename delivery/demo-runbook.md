# Demo-runbook: живой показ AI-buddy «Первый PR» (F7, Web 1)

Видео: `delivery/video/demo.webm` (25,8 с, WebM, записано Playwright с работающей сборки — тот же сценарий, что ниже).
Презентация: `delivery/presentation.pdf`. Режим AI во всех демо: **демо** (бейдж в шапке). Ключи не показываются.

## Подготовка (один раз, перед показом)

```bash
cd web
npm install
npm run dev          # http://127.0.0.1:5173, тестовый режим (адаптер)
```

Проверка готовности за 30 секунд: открыть адрес → «Войти как Вася Стажёр» → видна задача #TSK-101 и бейдж «Ресурс недоступен».

Автоматическая проверка пути: `npx playwright test` (5 сценариев, поднимает сервер сам).

## Сброс демо между прогонами

Вариант А (из UI): «Войти как Демооператор» → панель «Демооператор · имитатор согласования» → **«Сброс демо»** → выйти.
Вариант Б (браузер): DevTools → Application → Local Storage → Clear (очистит и сессию, и демофазу).
После сброса стажёр снова в состоянии «нет доступа, заявки нет».

## Сценарий показа — три голоса (~4 минуты)

Распределение: **Web 1** ведёт путь стажёра, **Web 2** объясняет интеграцию и права (действует за оператора), **AI** комментирует решения агента и границы достоверности.

| # | Действие на экране | Голос | Что сказать |
|---|---|---|---|
| 1 | Вход «Войти как Вася Стажёр». Карточка задачи, бейдж «Ресурс недоступен», «Режим AI: демо» | Web 1 | «Стажёр: первая задача назначена, репозиторий не открывается. Помощник уже знает задачу и разрешённую инструкцию». |
| 2 | Ввод «Не могу начать первую задачу. Что делать?» → уточнение | AI | «Свободная формулировка. Контекста мало — агент уточняет, а не гадает; факты берёт у сервера». |
| 3 | Ввод «Про репозиторий…» → карточка предложения (ресурс, цель, действие) | Web 1 | «Предложение явно показывает, что будет сделано. Без подтверждения ничего не создаётся». |
| 4 | Кнопка «Подтвердить» → REQ-2026-0142 «на согласовании» | Web 2 | «Сервер перепроверил право и записал заявку идемпотентно: повторный клик не создаст вторую. UI шлёт только ID предложения и ключ повтора». |
| 5 | F5 (перезагрузка страницы) → та же заявка REQ-2026-0142 | Web 1 | «Состояние переживает перезагрузку — заявка на сервере, а не в браузере». |
| 6 | Выйти → «Войти как Демооператор» → панель имитатора → «Одобрить заявку» | Web 2 | «Согласование — отдельная роль и отдельное действие. На живом стенде здесь HR-система; в прототипе — обозначенная панель имитации». |
| 7 | Вход стажёром: «Одобрена» + «Доступ: ещё не выдан», кнопки начала работы нет | Web 1 | «Решение по заявке и фактическое право — разные события: помощник не предлагает начинать, пока сервер не подтвердил доступ». |
| 8 | Оператор → «Выдать право» → стажёр → «Обновить состояние» | Web 2 | «Право выдаётся отдельно; интерфейс перечитывает effectiveAccess с сервера». |
| 9 | Появляется «Следующий шаг по задаче» → кнопка «Вернуться к задаче» → «Зафиксировано» | AI | «Событие task_returned подтверждает намерение стажёра — для метрики возврата к задаче. Права оно не даёт». |
| 10 | Вопрос из зала «покажи отказ» (опционально) | Web 2 | Оператор: «Отклонить» → у стажёра статус «Отклонена», закрытые сведения не появляются. |

## Типовые сбои и реакция

- Пустой экран/ошибка сети → экран ошибки с кнопкой «Повторить»; сначала восстановление серверного состояния, успех не подделывается.
- «Забыл» состояние → см. «Сброс демо».
- Порт занят → `npm run dev -- --port 5174` и открыть новый адрес.

## Что запрещено в демо
