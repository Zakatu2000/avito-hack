# Avito Start · AI-buddy — фронтенд-прототип

Веб-приложение для стажёров: путь адаптации, запросы (отгул, доступ), чат-бот-подсказник и вид наставника/руководителя. Прототип для кейса «AI-buddy: наставник для стажёров» хакатона Hack&Change 2026 от Авито.

- Бэкенда нет: все сервисы имитируются на клиенте через **MSW** с сохранением состояния в **localStorage**.
- ИИ не используется: бот — детерминированный движок по ключевым словам за интерфейсом `ChatEngine`.
- Все данные синтетические. Это не продукт Авито.

Живую витрину дизайн-системы и палитры можно посмотреть на странице `/design`.

## Порядок проверки сценариев

1. **Вход**: выбери «Аня Петрова».
2. **Главная**: прогресс-бар, карточка «Следующий шаг», дедлайны, быстрые действия.
3. **Путь адаптации**: нажми «Начать» → «Готово» у пункта без согласования; «Цели и OKR» доведи до «Ждёт согласования».
4. **Отгул**: Мои запросы → «Оформить отгул» → даты+причина → предпросмотр → «Отправить». Обнови страницу — запрос на месте.
5. **Доступ**: «Запросить доступ» → Confluence + обоснование → «Сохранить черновик» → в списке нажми «Отправить» у черновика.
6. **Чат**: спроси «как оформить отгул?», «нужен доступ к Jira», «что дальше по плану?», «квантовая механика» (fallback с контактом наставницы).
7. **Сбои**: открой dev-панель (🎛 справа внизу) → сбои «Всегда» → повтори действие: увидишь состояния ошибок и кнопку «Повторить» в чате. Верни «Выкл».
8. **Наставник**: выйди, войди как Марина Ким → «Команда»: стажёры с прогрессом, «Пункты на подтверждение» (подтверди 1:1 Ани), очередь запросов («Вынести решение» дважды проводит запрос до «Выдан»).
9. **Права**: войди как Аня и открой `/team` напрямую — состояние «Нет доступа» (мок-API отдаёт 403).
10. **Темы**: переключи светлую/тёмную тему в шапке; проверь мобильную ширину (<640px) — нижняя навигация и BottomSheet.

## Архитектура

```
src/
  api/        типизированный клиент (apiFetch + ApiError) и zod-схемы контрактов
  services/   интерфейс BuddyService (create_leave_request, request_access, get_checklist,
              approve_request, list_requests, ...) — единая точка замены MSW на реальные API
  mocks/      MSW-хендлеры, фикстуры JSON, БД в localStorage, имитация задержек/сбоев
  chat/       ChatEngine: интенты по ключевым словам, шаблоны, fallback
  stores/     zustand: auth, theme, dev, chat, toast
  components/ ui-кит (Button, Input, Select, DatePicker, Card, StatusBadge, ListItem,
              Timeline, Modal/BottomSheet, Toast, Skeleton, EmptyState, ProgressBar) + shell
  pages/      экраны (вход, главная, таймлайн, чат, запросы, контакты, база знаний,
              команда, метрики, /design)
```

Спецификации сценариев, прав и критериев приёмки — в папке [`specs/`](./specs/). Тесты ссылаются на них по номерам.

### Права по ролям

Роли: стажёр / наставник / руководитель. Запрет проверяется **на стороне мок-API** (403 + код `FORBIDDEN`), UI дополнительно показывает отдельное состояние «Нет доступа». Матрица прав — [specs/004-roles-permissions.md](./specs/004-roles-permissions.md).

### Замена MSW на реальные сервисы

1. Реализуй бэкенд, совместимый с zod-схемами из `src/api/schemas.ts` (это и есть контракт).
2. В `.env` (см. `.env.example`):

```
VITE_API_URL=https://api.example.com
VITE_ENABLE_MSW=false
```

3. UI, хуки и тесты менять не нужно — клиент строит URL из `VITE_API_URL`.

### AI-buddy и история чатов

Интегрированный экран отправляет сообщения в `POST /api/chat`. В Docker MSW
отключён: сервер использует общий классификатор, проверенный поиск по базе
знаний и настроенный AI-провайдер. В изолированных UI-тестах MSW сохраняет
контракт чата.

Список, создание, удаление и загрузка истории используют
`GET/POST /api/chats`, `DELETE /api/chats/:id` и
`GET /api/chats/:id/messages`. Идентификатор беседы передаётся вместе с
сообщением; история хранится сервером и изолирована по аккаунту.

## Допущения и ограничения

- Скриншоты в README не вложены — вместо них живая витрина `/design` (фиксация картинок не автоматизирована).
- Экватор/выпускной/опрос — пункты финального этапа таймлайна, отдельные приложения под них не делались (по условию «простой экран»).
- Метрики — макет на моковых числах, без агрегации по реальным данным.
- Тестовый вход без пароля: данные синтетические, авторизация имитируется заголовком `x-user-id`.
