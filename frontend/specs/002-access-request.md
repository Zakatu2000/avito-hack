# Spec 002 · Запрос доступа к системе

## Сценарий
Стажёр заполняет форму (система, обоснование, срок) → видит превью → отправляет → запрос проходит цепочку статусов. После перезагрузки страницы запрос остаётся в «Мои запросы».

## Инструменты имитируемых сервисов
- `GET /api/access-systems` — справочник систем (Confluence, Jira, репозиторий, Grafana, админ-панель).
- `POST /api/requests/access` — создание запроса (тело: система, обоснование ≥10 символов, срок в днях, `saveDraft?`).
- Далее см. общие операции с запросами в 003.

## Статусная цепочка
`draft → sent → approving → approved (Выдан) | rejected (Отклонён)`

- `draft` — сохранён черновиком, виден автору с кнопкой «Отправить».
- `sent` — отправлен, ждёт первого согласования.
- `approving` — первое согласование получено.
- `approved` — доступ выдан; для доступа финальный бейдж «Выдан».

## Согласующие
Руководитель (Олег Ветров). В превью показывается цепочка и согласующие.

## Валидация (zod, и на клиенте, и в мок-сервере)
- `system` — непустой id из справочника.
- `justification` — 10…300 символов.
- `durationDays` — целое 1…365.

## Критерии приёмки
- [x] Форма → превью (Modal на десктопе / BottomSheet на мобильном) → отправка или черновик.
- [x] Черновик можно отправить из списка «Мои запросы».
- [x] Наставник/руководитель доводит запрос до «Выдан» (кнопка «Вынести решение»).
- [x] Запрос и история статусов сохраняются в localStorage и переживают перезагрузку.
