# Spec 003 · Отгул через имитацию системы отсутствий

## Сценарий
Стажёр заполняет форму (даты, причина, комментарий) → превью → отправка. Статус и согласующие видны в «Мои запросы» с историей.

## Инструменты имитируемых сервисов
- `POST /api/requests/leave` — создание (даты ГГГГ-ММ-ДД, причина из справочника, комментарий, `saveDraft?`).
- `GET /api/requests` — список своих запросов (наставник/руководитель — все).
- `POST /api/requests/:id/approve|reject|send` — см. 002/004.

## Статусная цепочка
`draft → sent → approving → approved (Одобрен) | rejected`

## Согласующие
Наставница (Марина Ким) → руководитель (Олег Ветров). Отображаются в превью и в карточке запроса.

## Валидация
- Даты соответствуют `^\d{4}-\d{2}-\d{2}$`, конец не раньше начала (проверка на клиенте).
- Причина: `vacation | sick | personal | other`.
- Комментарий ≤300 символов, необязателен.

## Критерии приёмки
- [x] Полный сценарий «форма → превью → отправка → статус в списке» работает одним проходом.
- [x] Пустые даты не открывают превью — показываются ошибки полей.
- [x] История статусов с автором и временем ведётся для каждого запроса.
- [x] После перезагрузки запрос остаётся в списке.
