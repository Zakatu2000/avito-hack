# Spec 001 · Путь адаптации стажёра

## Сценарий
Стажёр открывает таймлайн адаптации, видит этапы «1 неделя», «2 неделя», «1 месяц», «2 месяц», «после 3 месяцев» (экватор, выпускной, опрос). Внутри этапов — пункты со статусами и следующим шагом.

## Инструменты имитируемых сервисов
- `GET /api/checklist` — этапы и пункты с прокинутым прогрессом текущего пользователя.
- `POST /api/checklist/items/:id/status` — смена статуса пункта (тело `{ status }`).
- Прогресс хранится в `localStorage` (`ai-buddy-db-v1`), переживает перезагрузку.

## Статусы пункта
| Статус | Кто выставляет |
| --- | --- |
| `not_started` | начальное значение |
| `in_progress` | стажёр («Начать») |
| `pending_approval` | стажёр («На проверку»), только для пунктов с `requiresApproval` |
| `done` | стажёр (без согласования) или наставник/руководитель (подтверждение, см. 004) |

## Требования
- У каждого пункта есть `nextStep` — конкретное следующее действие.
- Главная страница показывает прогресс-бар, карточку «Следующий шаг», дедлайны и быстрые действия.
- Пункт чек-листа «Доступы» ведёт на форму запроса доступа (экран 002).

## Критерии приёмки
- [x] Этапов 5, пункты содержат темы: чаты/каналы, доступы (Confluence, Jira), 1:1 с наставником, цели и OKR, документы/мануалы, защита персональных данных, подготовка к экватору.
- [x] Стажёр может довести пункт без согласования до `done` в два клика.
- [x] Попытка стажёра закрыть «согласовательный» пункт возвращает 403 (см. 004).
- [x] Изменения статуса сохраняются после перезагрузки страницы.
