# F1. Путь стажёра и макет состояний

AI-buddy «Первый PR», роль Web 1. Hack&Change 2026, кейс Авито.
Все данные синтетические. Сам PR в демо не создаётся.

## Сводка маршрута

Стажёр-бэкендер не может открыть учебный репозиторий первой задачи. Он описывает проблему своими словами в помощнике. Помощник проверяет назначение и доступ, предлагает заявку на доступ, после явного подтверждения возвращает её номер. Заявка переживает перезагрузку страницы. **Решение по заявке и фактическая выдача права — разные события:** пока сервер не подтвердил право, помощник не предлагает вернуться к задаче. Когда право подтверждено — показывает следующий шаг из назначенной задачи.

## Карта состояний экрана

```
[S0 пусто]            [S1 старт]          [S2 уточнение]
  нет задачи    →       задача есть   →      агент просит уточнить
                                     ↘
                                       [S3 предложение] ← повторный вопрос при живой заявке
                                          │  подтвердил (idempotency key)
                                          ▼
                                       [S4 заявка pending]  ←── обновление/повторный вход
                                          │  оператор одобрил (решение)
                                          ▼
                                       [S5 approved БЕЗ права] ←─ обновление
                                          │  оператор выдал право (effectiveAccess=granted)
                                          ▼
                                       [S6 доступ выдан → следующий шаг]
                                          │
                                    [S7 отказ] (решение = rejected)

  Любое состояние → [E1 сбой сети] [E2 тайм-аут] [E3 403] [E4 сессия истекла] → восстановление серверного состояния
```

## Состояния: что видит стажёр

Каждый блок: источник данных (контрактное поле) → доступное действие.

### S0. Пустое состояние — нет назначенной задачи
- **Видит:** «Задача пока не назначена. Попросите руководителя назначить первую задачу — после этого я помогу с доступами и шагами.» Экран приветствия, поле вопроса неактивно.
- **Источник:** `GET /api/workspace` → задача отсутствует.
- **Действие:** нет (только текст-подсказка). Кнопка «Обновить».

### S1. Старт без доступа (до диалога)
- **Видит:** карточку задачи («Задача #TSK-101 “Настроить CI для учебного сервиса”»), ссылку на разрешённую инструкцию, бейдж «Ресурс недоступен: git.avito.local/trainee/todo-service» и приглашение «Спросите своими словами». Индикатор режима AI (реальный/демо).
- **Источник:** `GET /api/workspace` → `taskId`, `resourceId`, `effectiveAccess: "denied"`, `requestStatus` отсутствует, `nextStep: "ask-assistant"`.
- **Действие:** ввести свободный вопрос. Открыть разрешённую инструкцию.

### S2. Неполный контекст (уточнение)
- **Видит:** ответ агента-уточнения: «Не понял, о каком ресурсе речь. Вы про репозиторий задачи #TSK-101 или о другом сервисе?» + чипы-варианты. Прежние сообщения сохраняются.
- **Источник:** `POST /api/messages` → `source: "agent"`, тип ответа — уточнение, предложения нет.
- **Действие:** ответить своими словами / выбрать чип.

### S3. Предложение заявки (перед подтверждением)
- **Видит:** карточку предложения: ресурс (`git.avito.local/trainee/todo-service`), цель (доступ для выполнения задачи #TSK-101), действие («Создать заявку на доступ»). Кнопки «Подтвердить» и «Не сейчас». Текст: «Заявка создаётся только после вашего подтверждения.»
- **Источник:** `POST /api/messages` → `proposalId`, поля предложения.
- **Действие:** подтвердить → `POST /api/proposals/{id}/confirm` (тело: идентификатор предложения + ключ повтора). Отмена — ничего не отправляется. Повторный клик по «Подтвердить» не создаёт вторую заявку (идемпотентность на сервере, UI блокирует кнопку и шлёт тот же ключ).

### S4. Заявка отправлена (ожидание согласования)
- **Видит:** карточку заявки: ID `REQ-2026-0142`, статус «На согласовании», отдельный бейдж «Доступ: пока нет». Пояснение: «Заявку смотрит руководитель. Решение и выдача права — два разных шага.» Кнопка «Обновить состояние».
- **Источник:** ответ `confirm` или `GET /api/workspace` → `requestId`, `requestStatus: "pending"`, `effectiveAccess: "denied"`.
- **Действие:** обновить состояние; продолжить диалог (помощник напоминает про существующую заявку, нового предложения не создаёт).

### S5. Одобрено, право ещё не выдано
- **Видит:** карточку заявки `REQ-2026-0142`, статус «Одобрена», бейдж «Доступ: ещё не выдан» и объяснение: «Заявку одобрили. Ждём, пока право появится у вас на ресурсе — обычно это минуты. Обновите состояние чуть позже.» Кнопки «Обновить состояние» / «Вопрос наставнику». Кнопки «Начать работу с репозиторием» НЕТ.
- **Источник:** `GET /api/workspace` → `requestStatus: "approved"`, `effectiveAccess` остаётся `"denied"` или `"unknown"`.
- **Действие:** обновить состояние; обратиться к наставнику (контакт из задачи).

### S6. Право выдано — следующий шаг из задачи
- **Видит:** зелёную карточку «Доступ подтверждён: git.avito.local/trainee/todo-service» и следующий шаг по задаче: «1) Склонируйте репозиторий. 2) Откройте инструкцию „Первый PR“ (разрешена). 3) Создайте ветку feat/...». Кнопка «Вернуться к задаче» — отправляет событие перехода (факт возврата фиксируется, но не выдаёт прав).
- **Источник:** `GET /api/workspace` → `effectiveAccess: "granted"`, `nextStep` из задачи.
- **Действие:** вернуться к задаче (событие `task_returned` по контракту; сигнал подтверждает намерение продолжить, а не наличие прав — права проверяет сервер).

### S7. Отказ по заявке
- **Видит:** карточку заявки со статусом «Отклонена» и текст: «Руководитель отклонил заявку. Причина указана в заявке. Можно уточнить детали у наставника.» Закрытые сведения не показываются.
- **Источник:** `GET /api/workspace` → `requestStatus: "rejected"`.
- **Действие:** вопрос наставнику; повторный вопрос помощнику (новое предложение возможно только через агента).

## Состояния ожидания и ошибок (тексты)

| Код | Когда | Что видит стажёр | Действие |
|---|---|---|---|
| W1 | любой запрос > 1 c (локальный) / в процессе LLM | скелетон/спиннер «Проверяю…» при сохранении доступа к экрану | ждать; экран не блокируется |
| E1 | сбой сети | «Не получилось связаться с сервером. Показываю последнее сохранённое состояние.» | «Повторить» — сначала `GET /api/workspace`, потом повтор действия |
| E2 | тайм-аут подтверждения | «Ответ не пришёл вовремя. Проверяю состояние заявки…» | автоматический `GET /api/workspace`; если заявка есть — показываем ID (не создаём вторую) |
| E3 | 403 на запрос | «Действие недоступно для вашей роли. Права проверяет сервер.» | вернуться к допустимому действию |
| E4 | сессия истекла | «Тестовая сессия истекла. Войдите заново.» | кнопка «Войти заново» (тестовый вход) |

Ключевые инварианты интерфейса: ошибка никогда не показывается как успех; две попытки подтвердить одно предложение → одна карточка с одним ID; свободный текст не создаёт заявку без подтверждения; режим AI виден всегда; ключи не показываются нигде.

## Примеры вопросов (передать A1)

1. «Не могу начать первую задачу. Что делать?»
2. «Почему не открывается репозиторий todo-service?»
3. «Мне нужен доступ к git, чтобы сделать первый PR»
4. «Что-то всё равно не открывается, я уже подавал заявку» (повтор после S4)
5. «Доступ уже дали? Могу начинать?» (в S5)

## Открытые вопросы для согласования

- **AI (A1):** формулировки переходов S2→S3 (когда агент предлагает заявку, а когда уточняет), тексты уточнений.
- **Web 2 (B1):** карта состояний и поля: подтверждена ли семантика `effectiveAccess=unknown` в S5; событие `task_returned` (S6) — имя и состав полей; коды ошибок 401/403/409/422 для E-состояний.
- До появления контракта всё вышеперечисленное считается фикстурой; живая проверка останется в F2/F5.

## Как проверить макет

Открыть `web/design/mockup.html` в браузере (без сборки). Переключатель состояний внизу показывает S0–S7 и экраны ошибок. Каждый экран подписан источником данных и доступным действием.
