# SDD · AI-buddy «Первый PR» · v1

## Цель и граница

Помочь стажёру разблокировать назначенную первую задачу. Агент читает только разрешённые сервером факты. Выполненное действие — номер заявки из сервиса, который отображён и сохранён. Фактическое право проверяется независимо от решения по заявке.

AI распознаёт смысл естественного вопроса и выбирает ветку диалога. Реальные идентификаторы, статусы и инструкции формирует детерминированная политика по серверному контексту. Внешняя модель возвращает только JSON {"intent": "<категория>"}. Этот контракт ограничивает последствия ошибки модели. Заявку по предложению создаёт отдельный серверный обработчик после согласия пользователя.

## Источники контекста A2

| Инструмент | Область видимости | Отсутствующий результат |
| --- | --- | --- |
| current_task() | Текущее назначение пользователя с проверкой команды и роли | null, передача наставнику |
| instruction() | Инструкция разрешённой команды и задачи | null, обращение к наставнику |
| effective_access() | Эффективное право на ресурс назначенной задачи | unknown, проверку требуется повторить |
| current_request() | Своя сохранённая заявка на этот ресурс | null, заявки нет |

Ограничение видимости выполняется в server/app.py до передачи контекста агенту. Идентичность берётся из cookie, исключены userId и роль из сообщения. Инструменты агенту передаются с уже ограниченным контекстом. Модель не выбирает произвольный объект для чтения. Внешнему провайдеру не передаются сессия, ключи и номер заявки.

В прототипе разрешённая база знаний состоит из учебной инструкции текущего назначения. Сервер сначала фильтрует доступ, затем передаёт фрагмент до 6000 символов. Поиск по другим командам и внешним материалам во время диалога отсутствует. При отсутствии инструкции агент направляет к наставнику.

## Доступные намерения A3

access_help, next_step, process_question, technical_issue, handoff, out_of_scope, unknown. Описание и примеры находятся в ai/intent_prompt.txt. Промпт задаёт формат и трактует пользовательский текст и инструкцию как данные. Валидатор отклоняет незавершённый ответ, лишние поля, неизвестную категорию и неверный тип.

Порядок выбора ответа фиксирован. Запрос вне области или явный чужой repo-ресурс направляется к наставнику без подтверждения существования объекта. Отсутствующее назначение и прямой запрос человека также передаются наставнику. Для технического симптома требуется шаг и текст ошибки. Для вопроса о процедуре цитируется доступная учебная инструкция. Неясный запрос вызывает уточнение. Далее для вопроса о доступе или следующем шаге применяется фактическое состояние из таблицы ниже.

| Условие | Результат | Изменение данных |
| --- | --- | --- |
| granted | Назвать следующий шаг из назначения | Нет |
| pending, право отсутствует | Показать сохранённый ID и ожидание согласования | Нет |
| approved, право отсутствует | Показать тот же ID, ожидание выдачи права | Нет |
| rejected | Показать ID и направить к наставнику | Нет |
| missing, заявки нет, инструкция доступна | propose_access на ресурс назначения | Сервер сохраняет предложение |
| unknown или отсутствует инструкция | Передача наставнику либо повтор проверки | Нет |
| Подтверждение предложения | Проверка текущих прав, версии и ключа повтора | Сервер создаёт заявку и возвращает ID |

## Внешний AI A4

Режим demo — детерминированный классификатор известных фраз. Режим live — OpenAI-совместимый Chat Completions endpoint с JSON-ответом. Сервис, модель, ключ и тайм-аут заданы переменными окружения. Ключ загружается только из AI_API_KEY. Автоматического чтения учётных данных других приложений нет.

Тайм-аут провайдера меньше тайм-аута API. На ошибке или некорректном ответе возвращается 503, предложение не сохраняется. Режим сохраняется live. Автоматическое переключение на demo отсутствует. Сервер повторно проверяет сессию и контекст после ожидания модели; при изменении выдаёт 409 без показа устаревшего ответа.

## Приёмка A5

Модульные случаи — ai/evals/cases.json и ai/tests/. Права, конкурентные подтверждения, перезапуск и повторная авторизация — server/tests/. Критерии: корректная ветка, допустимый источник, отсутствие неподтверждённых статусов в ответе, отсутствие побочных записей до подтверждения, сохранение режима. Реальные вызовы провайдера фиксируются отдельно от тестов с имитацией HTTP.

Процент успешных диалогов и покрытие строк — отдельные показатели. Для успешных сценариев обязательны права и соблюдение переходов независимо от качества распознавания намерения.
