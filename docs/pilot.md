# План пилота AI-buddy «Первый PR» (A6)

Владелец — AI. Метки: **[ИЗМЕРЕНИЕ]** — собирается прототипом/пилотом;
**[ОРИЕНТИР]** — внешние данные из источников (не цель и не обещание);
**[ГИПОТЕЗА]** — предположение со способом проверки.

## Дизайн пилота

Две сопоставимые учебные задачи с одинаковым блокером «нет доступа к учебному
репозиторию» (DEMO-02/03). Участники — стажёры учебного потока; случайное
распределение:

- **Группа A** — AI-buddy (текущая сборка);
- **Группа B** — обычный процесс (вопрос наставнику в чате).

Обе группы проходят путь: блокер → заявка → одобрение → выдача права →
возврат к задаче. Замер — одна неделя или до заполнения знаменателей.
Baseline (уровень без AI-buddy) собирается на группе B в ту же неделю —
отдельного «нулевого» периода не требуется.

## Зависимости (пробелы событий)

M2 и M4 требуют события `access_granted` — в коде пока не испускается
(`docs/events.md`, пробел №7). До пилота: эмитировать при выдаче права
демооператором (B5) либо замерять по смене `effectiveAccess` в workspace
(ручная сверка). M1: старт в прототипе — первое подготовленное предложение;
время «от появления проблемы до обращения» не наблюдается (README, B6).

  и не является целевым показателем прототипа.

- **[ГИПОТЕЗА H3]** M4 выше в группе A. Проверка: события + наблюдение.
