# Подключение корпоративного сервиса

| Участок | Как проверить прототип | Что потребуется для пилота |
| --- | --- | --- |
| Вход и роли | Стажёр и оператор входят раздельно, каждый запрос проверяется на сервере | Получать идентичность и роли из корпоративной авторизации. Маппинг групп и срок отзыва сессий согласовать с владельцем |
| Контекст и AI | POST /api/messages передаёт агенту разрешённое назначение, инструкцию, заявку и право | Подключить проверенный адаптер A4 и источники инструкций с проверкой доступа до поиска |
| Создание заявки | POST /api/proposals/{id}/confirm возвращает сохранённый ID при повторе | Согласовать внешний идентификатор, ключ идемпотентности и получение результата после тайм-аута. При раздельных БД предусмотреть доставку через outbox и сверку состояния |
| Согласование | Из отдельной сессии оператора одобрить заявку; в GET /api/workspace остаётся missing | Получать решение из сервиса согласования через его согласованный API или подписанное событие |
| Выдача права | Оператор вызывает grant; стажёр видит granted и следующий шаг | Перечитывать фактическое право из системы доступов и определить, как обрабатывать задержку и отзыв |

Учебный процесс и контракты синтетические. В демо решение и право хранятся в отдельных таблицах PostgreSQL; соединение с корпоративной средой Авито не выполняется.
