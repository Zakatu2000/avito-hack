## Поведение при ошибках (покрыто компонентными тестами, см. `src/App.test.tsx`, `src/components/ChatPanel.test.tsx`)

- **403 / неизвестная учётная запись** — вход отклоняется, сообщение об ошибке, данных нет (`TestApiClient.login` → `ApiError 403`); в UI нет способа передать роль из браузера.
- **Тайм-аут / сетевой сбой** — при отправке сообщения и подтверждении: сначала восстановление серверного состояния (`GET /api/workspace`), затем ошибка на экране; успех не показывается (нет «Заявка создана»), кнопка «Повторить» доступна.
- **Истечение сессии (401)** — возврат на экран входа с пояснением; после повторного входа карточка заявки восстанавливается с тем же ID.
- **Повторное подтверждение** — кнопка блокируется на время запроса, повторный клик невозможен, адаптер идемпотентен: одна карточка, один ID.

## Измерение отклика

- Метод: `Date.now()` в Playwright-спеке от клика до видимого изменения (`access-badge`). Задержка адаптера — 0 мс (локальная имитация), поэтому число характеризует отзывчивость UI-слоя: **~600 мс < 1 с** (порог из кейса).
- Ожидание модели имитировано `?latency=1500` (сценарий 4): UI не блокируется, ожидание обозначено.

## Ограничения и оставшиеся живые проверки

1. Прогон выполнен против **тестового адаптера**, а не живого Flask API: маршруты/тела запросов зафиксированы в `HttpApiClient` и совпадают с типами `src/api/types.ts`, но HTTP-статусы 401/403/409/422 от настоящего сервера проверятся после B4 (переключение: `VITE_API_MODE=http`, прокси на `127.0.0.1:8000`).
2. **Отдельная демосессия оператора**: в прогоне оператор действует через встроенную панель «Демооператор» (тестовый режим) со сменой входа в том же браузерном контексте — состояния адаптера живут в `localStorage`. С настоящим B5 действия оператора будут отдельной сессией/инструментом; сценарий готов к перекрытию без изменений UI-пути стажёра.
3. Реальный LLM (A4) не подключался: формулировки агента — фикстуры. После стыковки повторить сценарии 1–3 с `aiMode: "real"`.
4. Двухконтекстная проверка (стажёр и оператор в разных вкладках одновременно) возможна только с живым сервером — добавлю в F5-доопределение после B5.

## Расхождения для B4/B6 (передать)

- Маршруты, ожидаемые клиентом: `POST /api/session`, `DELETE /api/session`, `GET /api/workspace`, `POST /api/messages`, `POST /api/proposals/{id}/confirm`, `POST /api/events` (событие `task_returned`).
- Тело подтверждения: `{ "idempotencyKey": "..." }` — идентификатор предложения в URL, не в теле.
- Событие `task_returned`: подтверждает намерение стажёра продолжить задачу, не является полномочием; нужно для метрик A6 (отделяет клик от подтверждённого начала работы).
