# Замеры отклика UI: локальный адаптер, реальный API и ожидание live-модели

Обновлено: 2026-11-10 (финальная сборка, ветка `integration/final`). Все числа ниже — фактические прогоны в этой сессии; условия указаны для каждого замера. Данные синтетические.

## (а) UI-слой с локальным адаптером (TestApiClient)

Прогон: `npx playwright test` (5 сценариев, `web/e2e/main-path.spec.ts`, dev-сервер Vite 5, `VITE_API_MODE=test`).

| Сценарий | Длительность | Статус |
|---|---|---|
| Основной сценарий: вопрос → заявка → перезагрузка → одобрение → право → следующий шаг | 1,5 с | passed |
| После отказа закрытые сведения не появляются | 856 мс | passed |
| Уже имеющийся доступ: агент не предлагает заявку | 662 мс | passed |
| Долгий ответ (имитация `?latency=1500`): ожидание видно, интерфейс не блокируется | 5,6 с (включая искусственную задержку) | passed |
| Простое локальное действие реагирует быстрее 1 с | 541 мс | passed |

Итого: `5 passed (12.4s)`. Локальный UI-путь (клик → ответ адаптера) укладывается в 1 с.

## (б) Реальный путь: Flask API + PostgreSQL (demo-режим)

Прогон сквозного сценария: `BUDDY_LIVE_URL=http://127.0.0.1:5051 npx playwright test --config playwright.live.config.ts` (waitress + PostgreSQL 16, `BUDDY_DEMO_OPERATOR=1`, Chrome channel): полный путь вход → вопрос → подтверждение → перезагрузка (ID сохранён) → одобрение → выдача права → возврат к задаче — **passed, 3,2 с** целиком на сценарий.

Точечный замер «клик "Отправить" → появление ответа» (5 вопросов подряд, один и тот же стенде): `40, 175, 167, 168, 168 мс`; **медиана 168 мс**.

## (в) Ожание live-модели — не измерено

Живой вызов LLM-провайдера в этой сборке не выполнялся (нет API-ключа в сессии; см. `docs/qa/ai.md`, «Честные ограничения»). Ожидание складывается из `AI_TIMEOUT_SECONDS` (по умолчанию 8 с, ограничено бюджетом `BUDDY_AGENT_TIMEOUT`); фактические задержки провайдера будут измерены отдельно при наличии ключа: `cd ai && python -m evals.runner --live`. Исторические 3 smoke-запроса GLM предыдущей сборки (1,23–1,48 с на запрос) к этой версии кода не относятся.

## Известные ограничения замеров

- Замеры локальные, машина разработчика; сетевых задержек до внешнего провайдера нет.
- Chrome channel для live-прогона и bundled Chromium для локального — как в конфигах проекта.
- `Date.now()` в Playwright-сценариях не подменялся; время стенда включено в замер (б).
