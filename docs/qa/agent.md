## Команда

```powershell
cd ai
..\.venv\Scripts\python -m evals.runner          # офлайн-набор (CI-гейт)
..\.venv\Scripts\python -m evals.runner --live   # live-провайдер, нужны AI_* (отдельный прогон)
..\.venv\Scripts\python -m pytest --cov          # unit + контрактные + evals
```

## Набор

`ai/evals/dataset.json` — **58 записей**: 40 офлайн-диалогов CASE-01..CASE-13
(включая четыре перефразировки CASE-02, четыре prompt-injection атаки
CASE-10, сбой и невалидный ответ провайдера CASE-12, повтор после
«восстановления» — stateless агент даёт идентичное решение, формулировки без
ключевых слов и live-моки намерений CASE-13) плюс 18 live-записей
`EVAL-LIVE-*` (`providerMode=live`; без `--live` помечаются SKIP и не
мешают офлайн-гейту).

Каждый диалог фиксирует: ссылку на SDD, ожидаемое состояние Sxx, входные
факты (workspace из демоданных контракта), ожидаемые `kind`/`sourceId`/
`aiMode`, обязательные и запрещённые фрагменты текста, режим провайдера.
Дополнительно runner проверяет: зеркало серверной валидации
(`evals/server_check.py`), закрытое множество вызванных read-инструментов
(только 4 allow-listed), детерминизм повтора.

## Ограничения и честные оговорки

- Живые проверки: smoke 3/3 (2026-11-10, 1,33–2,15 с) и полный live-eval
  58/58 против `deepseek-flash` (2026-11-11, стабильность 5/5 прогонов);
  точность на произвольных формулировках — предмет пилота
  (`httpx.MockTransport`), поведенческий live-eval отдельно не измерялся.
- Доля успешных eval-диалогов — метрика поведения, **не** покрытие строк.
  Покрытие строк ai/ измеряется отдельно: `pytest --cov` (100% на момент A5,
  порог 90%); сведение с server/ без двойного учёта — B6.
- Датасет — синтетика (DEMO-01/02), тексты на русском, перефразировки
  ограничены набором; расширение — через добавление записей в dataset.json.
