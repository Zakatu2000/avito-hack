# События прототипа

Хранятся в onboarding_events. Конверт: event_id, assignment_id, name, request_id (если связан с заявкой), occurred_at (PostgreSQL timestamptz, единый момент времени). event_id — идентификатор для устранения дублей при выгрузке. assignment_id — синтетическое назначение.

| Событие | Когда записывается | Повторы |
| --- | --- | --- |
| blocker_reported | Сервер впервые сохранил предложение доступа | Одно на назначение |
| request_created | Запись pending-заявки в PostgreSQL | Одно на заявку |
| access_granted | Демосервис действительно добавил эффективное право | Одно на заявку, повтор grant ничего не добавляет |
| task_link_opened | Стажёр с проверенным правом нажал «Вернуться к задаче» | Одно на назначение |

Создание заявки и её событие входят в одну транзакцию. Выдача права и её событие также атомарны. Предложения и сессии сами по себе не создают заявку.

Назначение в этом прототипе соответствует одной первой учебной задаче. Начальные seeded-права не создают вымышленных исторических событий. Если право существовало до измерения, время ожидания неизвестно.

blocker_reported — распознанная помощником блокировка при подготовке предложения. Время до этого события, клики по недоступной ссылке и обращения к наставнику пока не инструментированы. task_link_opened подтверждает намерение, фактическое начало работы требует наблюдения учебного стенда.

Для пилота считайте длительности по одной assignment_id и request_id и сохраняйте исходы всех попыток. Сброс демоданных удаляет их зависимые события; выгрузку испытания необходимо выполнять до сброса.
