# Сервер

Flask/Waitress и PostgreSQL перенесены из `main/server`, AI-модуль — из `main/ai`.
Внутренние имена пакетов сохранены. Команды установки и запуска находятся в
[корневом README](../README.md).

- `server/app.py`: исходный API плюс подключение нового портального API;
- `server/portal_auth.py`: регистрация, парольный вход, сессии, CSRF и ограничение попыток;
- `server/portal_api.py`: контракт существующего frontend, роли, заявки, прогресс;
- `server/accounts.py`: интерактивное создание пользователей с заданной ролью;
- `server/migrations/007_portal.sql` и `008_portal_conversations.sql`: портал и постоянные чаты; миграции 001–006 сохранены побайтно;
- `server/portal_fixtures/`: серверная копия справочников и каталога интерфейса из `frontend`;
- `server/fixtures/`, `ai/`, `contracts/`: исходные данные, AI и контракт из `main`.

Существуют два разных каталога адаптации: исходный расширенный каталог
`/api/buddy/checklist` и каталог пяти этапов существующего интерфейса
`/api/checklist`. Их состояния намеренно хранятся отдельно: достоверного
соответствия пунктов между ветками нет. `/api/chat` читает прогресс именно
портального каталога, общий классификатор и безопасный поиск по базе знаний;
история AI-buddy сохраняется в `portal_conversations`/`portal_messages`.
Оригинальные `/api/buddy/*` сохранены для расширенного API и его тестов.

Заявки и выдачи в `/api/requests` — отдельная модель портала. `portal_grants`
записывает локальную демо-выдачу в той же транзакции, в которой frontend получает
статус `approved` («Выдан»). Реальные Confluence/Jira/HR-провайдеры не подключены.
Исходный поток `access_requests/access_grants` не смешивается с этой моделью.

По умолчанию AI работает без внешних запросов (`demo`). Для live-режима нужны
`AI_MODE=live`, `AI_BASE_URL`, `AI_MODEL`, `AI_API_KEY` и
`BUDDY_AGENT_FACTORY=agent.factory:create_agent`; секреты храните только локально.
При недоступности вызванного провайдера API возвращает 503.

Документы в `docs/` описывают исходный сервер и его демо-сценарии из `main`;
при расхождениях по интеграции используйте `../README.md` и `../INTEGRATION.md`.
