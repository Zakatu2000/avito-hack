# SDD портала адаптации

У портала один расчёт следующего шага. Главная, таймлайн и чат читают его через сервер. Состояния старых каталогов находятся в своих таблицах. Карточки «Знакомство с командой» (`wk1-team` и `common-03`) объединены по общему критерию самоподтверждения. У согласованной встречи и общего материала о работе с наставником разные критерии.

| Вход | Факты | Результат |
| --- | --- | --- |
| «Что мне делать сегодня?» | Видимые пункты, зависимости, этап, действующие выдачи, блокеры | Доступный шаг быстрого старта, затем доступный пункт общего плана. При отсутствии действия — причина и ссылка |
| «Почему я не могу продолжить?» или помощь по пункту | Серверный контекст владельца | Причина, ссылка на запрос доступа, наставника или связанное обращение |
| «Не запускается окружение» | Результаты поиска по роли и направлению | Учебная инструкция с меткой источника и ссылка на форму техподдержки |
| «Мне нужен доступ к репозиторию» | Срок действующей демо-выдачи | Действующее право либо ссылка на форму с системой и контекстом задачи |
| «Хочу обсудить первую задачу с наставником» | Доступный пункт или отсутствие контекста | Форма консультации с явной отправкой. Согласованный слот хранится локально |
| «Где изучить микросервисы?» | Сохранённый чек-лист и разрешённые источники | Найденные материалы и форма запроса для темы |
| Пароль, токен или попытка выдать права из чата | Закрытый классификатор и серверные права | Ответ о границе полномочий. Отправку, согласование и выдачу выполняют отдельные API |

При выдаче всех необходимых демо-доступов сервер завершает пункт после подтверждения знакомства с наставником и командой. Просроченная выдача снова блокирует фактическое использование, сохраняя историю выполнения. Техническое обращение блокирует связанный пункт до проверки автором. Открытие назначенной учебной задачи и отметка начала работы — разные события. Наставник или руководитель команды подтверждает отметку начала, после чего она участвует в метрике.

В live-режиме модель формулирует ответ на допустимые вопросы с источниками. Принимаются только ссылки на извлечённые фрагменты. Ссылки в интерфейсе, статусы и доступные действия формирует сервер. После ожидания модели обновляются сессия и факты. Отказ провайдера даёт `503`, изменение фактов — `409`, истечение сессии — `401`. Ответы по правилам и ответы с моделью имеют разные метки.

## Измерения

Портальные события записываются в одной транзакции с операцией. В них входят технический ID, тип и время. Длительности считаются по завершённым парам событий. Стартовые даты профилей имеют точность до дня. Доля самообслуживания использует ответы с явным отзывом. У метрик есть размер выборки. Набор в `test_synthetic_metrics` воспроизводит расчёт на синтетических событиях.

У портальных запросов с `messageId` ответ содержит режим, способ обработки и источники. Прежние клиенты могут отправлять только `message`. Операции над новыми заявками принимают `X-Request-Version` со значением `updatedAt`. Смена состояния между чтением и записью возвращает `409`.
